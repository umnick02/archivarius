# Archivarius

Библиотека интерактивных архитектурных карт. При приближении подсистема раскрывает
свои компоненты, а общие стрелки — конкретные взаимодействия. Геометрия остаётся
неподвижной между уровнями масштаба.

На вход подаётся **архитектурная модель**, независимая от языка, репозитория и
сборки проекта. Это может быть URL JSON-файла, выбранный пользователем `File` /
`Blob` или уже разобранный объект. Данные проекта не встраиваются в библиотеку.
Координаты и отдельный файл раскладки передавать не требуется.

## Подключение

Пакет пока устанавливается из Git, в npm registry он не опубликован:

```sh
npm install git+ssh://git@github.com/umnick02/archivarius.git react@19 react-dom@19
```

При установке из Git `prepare` собирает пакет. Для установки с отключёнными
скриптами сначала соберите архив в клоне репозитория:

```sh
npm ci --ignore-scripts
npm run build
npm pack --ignore-scripts
```

Полученный `archivarius-0.1.0.tgz` можно установить в другом проекте через
`npm install --ignore-scripts /path/to/archivarius-0.1.0.tgz`.

Пакет — ESM для приложения с браузерным сборщиком. Проверено с React 19 и Vite 8.
Импортируйте стили и выделите контейнеру ненулевую ширину и высоту; рекомендуемый
минимум — 320 × 400 px. React используется внутри и в варианте обычного JavaScript.

```js
import { mountArchitectureMap } from 'archivarius';
import 'archivarius/style.css';

const map = mountArchitectureMap(document.getElementById('map'), {
  source: '/architecture.json',
  locale: 'ru',
});

await map.ready;
```

Контейнер должен быть пустым. `map.ready` завершается после первой загрузки,
построения карты и установки начального масштаба. Ошибку нужно обработать как
обычное отклонение Promise; она также отображается в карте.

```js
await map.load(fileInput.files[0]);
await map.focus(componentKey);
await map.home();
map.destroy();
```

Новая `load()` заменяет предыдущую загрузку. Её незавершённый Promise отклоняется
с `AbortError`; старый результат не может перезаписать новый. При ошибке новая
карта не показывается как успешно загруженная. `destroy()` снимает обработчики,
отменяет незавершённую загрузку и освобождает контейнер; повторный вызов допустим.
`snapshot()` возвращает копию текущего состояния навигации для интеграционных
проверок, не изменяя модель.

## React

```jsx
import { ArchitectureMap } from 'archivarius';
import 'archivarius/style.css';

export function ProjectArchitecture() {
  return (
    <ArchitectureMap
      source="/architecture.json"
      locale="ru"
      style={{ height: 720 }}
      onReady={(map) => console.log(map.snapshot())}
      onError={(error) => console.error(error)}
    />
  );
}
```

`ref` предоставляет `home()`, `focus(key)` и `snapshot()`. Смена `source` загружает
новую модель и сбрасывает навигацию. При передаче объекта сохраняйте его ссылку
между рендерами, пока данные не меняются. Поддержаны `ru` и `en`; текст самой
архитектуры остаётся таким, каким он записан в модели. Несколько карт имеют
раздельные состояния, обработчики клавиатуры и идентификаторы. Стили ограничены
контейнером `.archivarius`, адаптация зависит от ширины контейнера.

## Контракт файла

[Полный пример](examples/basic/public/architecture.json),
[JSON Schema](assets/model.schema.json) и
[смысловые правила](assets/contracts.json) находятся в отдельных файлах.
Схема экспортируется также как `archivarius/model.schema.json`.

Верхний уровень модели:

| Поле        | Значение                                                                  |
| ----------- | ------------------------------------------------------------------------- |
| `version`   | `3` — версия контракта, не пакета                                         |
| `scope`     | `target` — карта описывает целевое устройство                             |
| `title`     | Необязательное название проекта / карты                                   |
| `entry`     | Ключ конкретного конечного участника, от которого проверяется связанность |
| `nodes`     | Дерево компонентов и подсистем                                            |
| `relations` | Направленные взаимодействия между конечными участниками                   |

У блока обязательны `key`, `title`, `summary`, `kind`, `zone`, `rules`, `detail` и
`implemented`. `kind` — `subsystem`, `component`, `store` или `external`;
`zone` — `presentation`, `application`, `infrastructure`, `pure` или `external`.
Это логические роли, не имена фреймворков или обязательные отдельные сервисы.

`detail: mapped` требует `kind: subsystem` и непустые `children`.
`detail: boundary` требует `detailNote` и запрещает `children`. Правила записываются
массивом `{title, text}`; этот массив может быть пустым. `example` необязателен.
Глубина разных веток может различаться; не нужно придумывать неизвестные модули.

У связи обязательны `key`, `from`, `to`, `kind`, `channel`, `label`, `payload`,
`meaning` и `implemented`. `kind` — `data`, `command` или `state`. Оба конца —
конкретные конечные участники. На общем масштабе библиотека представляет их
родителями и объединяет только совпадающие направление, тип, канал и подпись.
Содержимое каждой исходной связи остаётся доступным в пояснении.

Ключи состоят из строчных латинских букв, цифр и дефисов, начинаются с буквы и
уникальны в своём списке сущностей. Названия могут быть на любом языке.
Неизвестные поля отклоняются: опечатка не должна молча изменять смысл контракта.

Каждый конечный участник имеет взаимодействие и принадлежит общей связанной
системе; отдельные острова недопустимы. Каждая раскрытая подсистема имеет связь
через свою границу. Вложенность не заменяет взаимодействия. Поэтому схема файла
проверяет структуру, а валидатор библиотеки дополнительно проверяет весь граф.

**Полная реализация — один булев признак.** `implemented: true` означает, что весь
описанный контракт работает в достижимом пути приложения и проверен. Обязательно
`implementationEvidence`: краткое основание с проверенным путём, версией кода и
результатами проверок. При `false` полная реализация не подтверждена; часть кода
может существовать. Промежуточных статусов и процентов нет.

У подтверждённого блока должны быть подтверждены все его части и входящие,
исходящие и внутренние связи. Готовность детей не выставляет `true` родителю
автоматически: требуется проверка всего его контракта. Общая стрелка имеет `true`
только при `true` всех составляющих. Валидатор проверяет наличие основания и
согласованность отметок, но не исследует код и не доказывает правдивость текста.

Проверка файла без React, DOM или раскладки:

```js
import { readFile } from 'node:fs/promises';
import { parseArchitecture, validateArchitecture } from 'archivarius/core';

const model = parseArchitecture(await readFile('architecture.json', 'utf8'));
const { valid, errors } = validateArchitecture(model);
```

`parseArchitecture()` выбрасывает `ArchitectureError` с `code` и `issues`.
`validateArchitecture()` принимает неизвестный объект и возвращает результат.
Эти функции можно использовать в проверках проекта перед публикацией карты.

## Данные и размещение

По умолчанию URL-файл загружается обычным `fetch`; действуют правила origin/CORS
приложения. `File` и `Blob` читаются локально. Библиотека не отправляет модель на
сервер, не сканирует репозитории и не сохраняет правки в исходный файл.

Подписи и правила поставляются отдельными JSON-ресурсами в `dist/assets/`.
Сборщик должен сохранить ссылки `new URL(..., import.meta.url)`; Vite проверяется
на готовом пакете, включая размещение под вложенным URL. Если ваш сборщик иначе
обрабатывает ресурсы, скопируйте `dist/assets/` пакета на свой статический сервер
и передайте `assetsBaseUrl: '/archivarius-assets/'`. Этот каталог должен содержать
`ru.json`, `en.json`, `contracts.json` и `contracts.en.json`.

ELK.js загружается отдельным модулем при построении. В этой версии вычисление
раскладки выполняется в браузере без отдельного Web Worker; крупная модель может
временно занять основной поток. При отмене загрузки результат отбрасывается,
текущий синхронный шаг не прерывается. Обновление модели запускает новый расчёт,
масштабирование и выделение типа — нет. Автоматической актуализации из кода пока
нет; отметки реализации пересматриваются при соответствующих изменениях проекта.

## Разработка и проверки

```sh
npm ci --ignore-scripts
npm run build
npm run dev
```

Пример доступен на `http://127.0.0.1:44889/`; в нём можно открыть свой JSON-файл.
`npm run build:example` и `npm run preview` проверяют его production-сборку.

`npm run check` собирает библиотеку, проверяет модель, геометрию, ресурсы и
изоляцию CSS, затем устанавливает tarball в отдельный проект, проверяет публичные
типы и собирает потребителя под `/embedded/maps/`. Для браузерных проверок после
этого запустите preview потребителя на порту 44891 и Chrome с CDP на порту 44890,
затем `npm run test:browser`. Временные потребители, архивы и снимки — в `.runtime/`.

Основа: [React Flow](https://reactflow.dev/api-reference/react-flow-provider) для
интерактивного графа и независимых экземпляров,
[ELK.js](https://github.com/kieler/elkjs) для раскладки. JSON-ресурсы сохраняются
отдельно от JavaScript, включая сборку потребителя; это проверяется тестами.
