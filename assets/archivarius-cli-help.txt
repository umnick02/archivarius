Archivarius

  archivarius init <project.json> [--title <text>] [--json]
  archivarius validate <model.json> [--json]
  archivarius reference <model.json> --output <architecture.md> [--check]
  archivarius readme <project.json> --output <README.md> [--check]
  archivarius documents <project.json> --output <directory> [--check] [--json]
  archivarius graph <model.json> --output <graph.dot> [--format dot|mermaid|table] [--check]
  archivarius history <project.json> --output <HISTORY.md> [--check]
  archivarius read <project.json> --focus <key> [--focus <key>]
  archivarius context <project.json> --focus <key> [--focus <key>] [--output <receipt.json>]
  archivarius archive <project.json>
  archivarius git-history <project.json> [--json]
  archivarius diff <project.json> [--against <project.json>] [--stale] [--output <diff.json>] [--json]
  archivarius apply <project.json> --context <context.json> --change <change.json>
  archivarius run <project.json> --focus <check-key> --result <new-key> --evidence <relative-path.json> [--timeout <seconds>] [--resolves <result-key> --resolution <text>]
  archivarius verify <project.json>
  archivarius reconcile <project.json> [--json]

validate checks both the file schema and all graph invariants.
init writes the smallest valid snapshot — one scope, source, requirement and criterion — and refuses to write over an existing file.
--json returns machine-readable diagnostics with JSON Pointer paths.
reference generates one Markdown file from that same validated model. It never edits the model.
readme generates the landing page: the scope, one table per record type, and only the parts the model binds to a file.
documents renders document records to their declared Markdown/JSON paths under the output directory.
graph writes the same projection the map draws as Graphviz DOT, a Mermaid flowchart or a record table.
history writes the release history: every stored snapshot walked in pairs, with the records each version added, removed and changed.
--check compares the output with fresh generation and exits unsuccessfully on drift.
read returns focused contracts and owning sections without review metadata.
context returns the exact edit receipt; --output saves it and prints the focused read view.
apply checks the read closure, permits disjoint edits and preserves history atomically.
archive moves existing history to immutable adjacent hash-linked segments; node reads hydrate them.
git-history moves a fully committed model and archive to Git-backed history without changing Git or deleting files. After migration, old sidecars may be removed; the repository must retain the referenced commits. Pending uncommitted revisions stay in the working JSON until a later apply can read them from Git.
diff reports the added, removed and changed records against another snapshot, or against the model's own most recent stored manifest.
--against names the earlier snapshot file; --stale keeps only the reading list: every record that lost its basis, with the definition that moved.
run explicitly executes the check's command and records its actual outcome.
--timeout gives the command a budget in seconds, 60 by default; a command that outlives it is recorded as a failure.
--resolves names an earlier failed run of the same check that this one clears, and --resolution says why it no longer stands; naming one without the other is refused.
verify reads bound files and check artifacts; missing confirmation exits with code 1.
reconcile reads the imports the sources actually have and reports every declared relation the code lost, every dependency no record declares and the edges it could attribute to no described part; a disagreement exits with code 1.
Exit codes: 0 success, 1 invalid model / stale document / I/O failure, 2 invalid arguments.
